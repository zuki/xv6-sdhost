# idle_procの問題

- 実行可能なプロセスがない場合、各cpuに設定されているidleプロセスが実行される
- このidleプロセスは`SYS_sched_yield`シスコールを繰り返し実行するもの
- このシステコールは`yield()`（cpuを明け渡す）を実行するだけである。
- そのため何も実行するプロセスがない場合、このidleプロセスが無限に実行され
  cpuがほぼ100%実行されることになる。
- milkvでの実装では次のように割り込みを有効にして`wfi`命令を実行し。
  割り込みが起きるまでスリープするというようになっており、実際、実行する
  プロセスがない場合、cpuはスリープしてほぼ0%である。
- raspiのidleプロセスでもこれができないか検討する。

## sys_yield()でwfi()を実行

```c
long sys_yield(void)
{
    wfi();              // ここでwfiを実行
    yield();
    return 0;
}
```

- 実行はされるが、至るところでストールしたかのように処理速度が低下し、
  shでの入力応答もカクカクする。

## wfe()に変更

```c
long sys_yield(void)
{
    wfe();              // wfeに変更
    yield();
    return 0;
}
```

- wfi()の代わりにwfe()を使ったところ、処理速度の低下がなくなった。
- cpuもwfe()のない場合より熱くならないように思われる。
